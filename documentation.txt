GYM / TRAINER BUSINESS SAAS
SYSTEM DOCUMENTATION

---

1. INTRODUCTION

---

This document describes the architecture, features, database schema, and implementation details of the Gym / Trainer Business SaaS platform.

The platform enables gym owners to manage members, trainers, memberships, payments, and attendance using a cloud-based system.

The system is designed as a multi-tenant SaaS product where multiple gyms can use the platform independently.

Primary goals:

• Simplify gym operations
• Track memberships and payments
• Manage trainers and members
• Monitor attendance and analytics
• Automate reminders and notifications

---

2. TARGET USERS

---

The platform supports three main user roles.

ADMIN (Gym Owner)
Responsibilities:
• Manage gym operations
• Add members and trainers
• Manage membership plans
• Track payments
• View analytics dashboard

TRAINER
Responsibilities:
• View assigned members
• Track client progress
• Manage training schedules

MEMBER
Responsibilities:
• View membership details
• Check attendance
• Receive notifications
• View assigned trainer

---

3. SYSTEM ARCHITECTURE

---

The platform follows a standard modern SaaS architecture.

Frontend Layer
Web dashboard and mobile application used by users.

API Layer
Handles business logic and communication between frontend and database.

Backend Services
Responsible for authentication, data management, and core business operations.

Database Layer
Stores all persistent data.

Architecture Flow:

Client Application
|
REST API
|
Backend Services
|
Database

5. MULTI TENANT STRUCTURE

---

The system supports multiple gyms using the same platform.

Each gym has isolated data.

Example structure:

Gym A
Members
Trainers
Payments

Gym B
Members
Trainers
Payments

Data isolation is maintained using gym_id in all related tables.
